# Personal Telegram Universal Video Downloader

بوت شخصي للمالك فقط. يستقبل روابط الفيديو، يحلل الـ formats المتاحة، يختار أعلى جودة مناسبة تحت 48 MB، ويضغط الفيديو تلقائيًا إذا لم توجد جودة مناسبة. يدعم أيضًا روابط الفيديو المباشرة كـ fallback.

## ما تم إصلاحه

- اختيار الجودة بناءً على الحجم المتوقع بدل تحميل 720p ثم حذفها.
- اختيار أعلى جودة ممكنة تحت 48 MB.
- ضغط تكيفي بعدة محاولات عند عدم وجود format مناسب للحجم.
- fallback للروابط المباشرة مثل MP4/WebM.
- تحسين محاولات yt-dlp مع Cookies عند الحاجة.
- تجهيز yt-dlp مع EJS + Deno لتحسين دعم المواقع التي تحتاج JavaScript، خصوصًا YouTube.
- البوت يعمل للمالك المحدد في `ADMIN_USER_ID` فقط.
- اختيار جروب الإرسال من `/admin` أو `/setgroup`.
- حفظ جروب الاستقبال في `bot_state.json` داخل المستودع حتى لا يضيع مع تبديل GitHub Runner.
- حفظ قائمة الجروبات المسجلة في نفس الحالة.
- fallback من `send_video` إلى `send_document`.
- منع أكثر من Job تحميل في نفس الوقت افتراضيًا.
- تنظيف الملفات المؤقتة دائمًا.

## GitHub Secrets المطلوبة

### `BOT_TOKEN`
Token البوت من BotFather.

### `ADMIN_USER_ID`
Telegram numeric user ID الخاص بك فقط.

### `COOKIES_B64`
اختياري. حوّل ملف `cookies.txt` إلى Base64 وضع الناتج في GitHub Secret بهذا الاسم. الـ workflow ينشئ `cookies.txt` تلقائيًا أثناء التشغيل ويحذفه مع الـ Runner. لا تضع Cookies داخل Git أو داخل الكود.

## اختيار الجروب

1. أضف البوت إلى الجروب المطلوب.
2. من داخل الجروب أرسل `/setgroup` لتعيينه فورًا، أو سجله ثم استخدم `/admin` من محادثتك مع البوت.
3. اختيار الجروب محفوظ في `bot_state.json` ويتم مزامنته مع المستودع.
4. لتغييره لاحقًا، استخدم `/setgroup` في الجروب الجديد أو `/admin`.

## الحد والحجم

Telegram bots حاليًا يمكنها إرسال ملفات حتى 50 MB. المشروع يستخدم حدًا آمنًا 48 MB ويستهدف 47 MB عند الضغط لتجنب رفض الملف بسبب تجاوز بسيط.

## تشغيل GitHub Actions

الـ workflow يستخدم `contents: write` لأن البوت يحتاج تحديث `bot_state.json` عند تغيير جروب الاستقبال. لا يوجد self-dispatch loop؛ التشغيل يتم بواسطة GitHub schedule/dispatch مع `concurrency` لمنع تشغيل نسختين معًا.
