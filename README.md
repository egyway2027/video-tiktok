Personal Telegram Universal Video Downloader

بوت Telegram شخصي للمالك فقط.

يستقبل روابط الفيديو، يحلل الـ formats المتاحة، ويختار أعلى جودة ممكنة ضمن حد Telegram الآمن، مع ضغط تلقائي عند الحاجة، ثم يرسل الفيديوهات داخل Topics في الجروب المختار.

المميزات

دعم yt-dlp للمواقع التي يدعمها، مع fallback للروابط المباشرة مثل MP4/WebM/MOV.

تحسين التعامل مع Facebook وInstagram وTikTok وX عبر Cookies وBrowser Impersonation عند الحاجة.

دعم JavaScript/EJS عبر Deno للمواقع التي تحتاجه.

تحليل الـ formats قبل التحميل واختيار أعلى جودة ممكنة ضمن 48 MB عندما يكون الحجم قابلًا للتقدير.

ضغط تكيفي متعدد المحاولات عند عدم وجود جودة مناسبة للحجم.

هدف الضغط حوالي 47 MB مع هامش أمان لحد Telegram.

تنظيف الروابط ومعاملات التتبع لتقليل اعتبار نفس المحتوى روابط مختلفة.

❌ إلغاء

اختيار Topic يدويًا لكل رابط.

تسجيل Topics داخل الجروب باستخدام /settopic.

حفظ آخر Topic مختار واستخدامه كافتراضي.

تجميع 4 فيديوهات في Media Group/Album واحد داخل نفس الـTopic.

إذا كان المتاح أقل من 4 فيديوهات، يتم إرسال الموجود بعد 30 ثانية.

حماية محتوى رسائل الفيديو من إعادة التوجيه/الحفظ عبر protect_content.

اختيار جروب الاستقبال ديناميكيًا من /admin أو /setgroup.

حفظ الجروب والـTopics والحالة في bot_state.json مع مزامنة GitHub.

البوت مقيد على ADMIN_USER_ID فقط.

fallback من send_media_group إلى إرسال الفيديوهات منفردة عند الحاجة.

تنظيف الملفات المؤقتة وإعادة المحاولة للرفع الفاشل.

GitHub Secrets المطلوبة

BOT_TOKEN

Token البوت من BotFather.

ADMIN_USER_ID

Telegram numeric user ID الخاص بمالك البوت.

COOKIES_B64

اختياري لكنه مهم للمواقع أو الفيديوهات التي تتطلب تسجيل الدخول.

حوّل ملف cookies.txt إلى Base64 وضع الناتج في GitHub Secret بهذا الاسم. الـWorkflow ينشئ cookies.txt أثناء التشغيل ويحذفه مع الـRunner.

لا تضع BOT_TOKEN أو COOKIES_B64 داخل Git.

Topics

أنشئ Topics يدويًا داخل الجروب، ثم ادخل كل Topic واستخدم:

/settopic

البوت يسجل الـmessage_thread_id واسم الموضوع ويحفظهما.

من محادثتك الخاصة مع البوت يمكنك استخدام:

/topics

لاختيار الـTopic الافتراضي، أو /admin لإدارة الجروب والـTopics.

طريقة تحميل الرابط

أرسل الرابط للبوت.

اختر الـTopic الذي تريد حفظ الفيديو فيه.

يبدأ التحليل والتحميل واختيار الجودة.

إذا كان الفيديو أقل من 48 MB بدون ضغط، يتم إرساله كما هو.

إذا تجاوز 48 MB ولم توجد جودة مناسبة، يتم ضغطه تلقائيًا.

كل 4 فيديوهات جاهزة للـTopic نفسه يتم إرسالها كـAlbum واحد.

اختيار الجودة والحجم

حد Telegram المستخدم في المشروع هو 48 MB كحد أمان. عند الضغط يتم استهداف حوالي 47 MB لتجنب رفض Telegram بسبب تجاوز بسيط.

إذا كانت هناك جودة 720p تحت الحد، يتم اختيارها بدل 480p. وإذا كانت 720p أكبر من الحد و480p مناسبة، يتم اختيار 480p، وهكذا.

كلمة السر وحماية الرؤية

Telegram لا يوفر للـBot صلاحية تجعل رسالة فيديو واحدة مرئية لعضو وغير مرئية لعضو آخر داخل نفس الجروب. لذلك لا يمكن تنفيذ "كلمة سر لإظهار نفس رسائل الفيديو داخل الجروب" كصلاحية قراءة مستقلة لكل عضو.

المشروع يستخدم protect_content لتقليل إعادة التوجيه والحفظ، بينما صلاحيات البوت الإدارية نفسها محصورة في ADMIN_USER_ID.

إذا أردت مستقبلًا نظام محتوى خاص بكلمة مرور، يجب أن يكون التوزيع عبر البوت/محادثة خاصة بدل الاعتماد على إخفاء رسائل المجموعة عن أعضاء مختلفين.

GitHub Actions

الـworkflow يثبت Python وFFmpeg والاعتماديات وDeno، وينشئ ملف Cookies عند وجود COOKIES_B64، ثم يشغل البوت.

يستخدم concurrency لمنع تشغيل أكثر من نسخة في نفس الوقت، وcontents: write لأن البوت يحدّث bot_state.json عند تغيير الجروب أو Topic.
